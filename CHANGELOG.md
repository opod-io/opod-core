What's shipped in Opod, organized by area. For the per-release diff see
[Releases](https://github.com/opod-io/opod/releases) — every `feat:` /

## Core (single-node, works today)

- Single binary (`go build ./cmd/opod` → ~25 MB) — no Python or Docker required
- **OpenAI-compatible** API (`/v1/chat/completions`, `/v1/embeddings`, `/v1/models`) — Cursor, Aider, Continue, Zed, OpenAI SDK
- **Anthropic-compatible** API (`/v1/messages`, `/v1/messages/count_tokens`) — Claude Code, Anthropic SDK
- Streaming (SSE) for both protocols, with proper client-disconnect handling (no goroutine leaks; bounded drain on cancel)
- **Hybrid fallback** — requests for `claude-*` or `gpt-*` transparently proxy to the real Anthropic / OpenAI API (set `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`); protocol mismatch (e.g., Claude model on OpenAI route) returns a clear 400
- Engine drivers: **Ollama**, **vLLM**, **MLX-LM**, **llama.cpp** (single-node *and* RPC mode; `llama-server` is **auto-spawned** when the catalog entry has `source.repo` set — no manual `llama-server` step)
- Engine endpoints + API keys configurable per engine via env (`OPOD_VLLM_ENDPOINT`, `OPOD_VLLM_API_KEY`, …; the unprefixed `VLLM_API_KEY` still works as a deprecated fallback)
- Hardware auto-detection (mac + linux + NVIDIA) and auto-pick a default model
- Catalog with **41 curated model entries** spanning Llama, Qwen, Gemma, MiMo, DeepSeek, GPT-OSS, Mistral, Phi, Kimi, GLM, Nemotron, StepFun, Moondream, Pixtral families — with `released:` dates and license metadata enforced by CI
- **Non-catalog installs (4 paths)** — `opod model add hf:owner/repo`, `ollama:tag`, or `file:/abs/path.gguf` skip the catalog and pull anything the configured engine supports; `opod model add --from <my.yaml>` installs a user-written entry and persists it into `~/.opod/catalog/`; users can also drop YAML files directly into `~/.opod/catalog/<id>.yaml` and `opod model add <id>` treats them like curated entries. Dashboard's "Add custom model" input + `POST /admin/v1/models` accept the scheme prefixes too.
- **Per-key model allowlist** — `opod token create alice --models qwen-coder-7b,gpt-4o-mini` (or `--models 'claude-*'` for vendor families) restricts an API key to specific model ids. Unauthorized requests return HTTP 403 `model_not_allowed` with the allowed list, and refusals land in the audit log. Edit via `opod token edit <id> --add-model X / --remove-model Y / --set-models a,b,c / --clear-models`, dashboard Tokens tab, or `PATCH /admin/v1/tokens/{id}`. Existing keys (NULL allowlist) keep working unchanged.
- **Per-request fallbacks + retries** — `/v1/chat/completions` and `/v1/messages` accept a `opod` block in the request body (`opod.fallbacks`, `opod.num_retries`, `opod.retry_backoff_ms`) or the equivalent `X-Opod-Fallbacks` / `X-Opod-Num-Retries` / `X-Opod-Retry-Backoff-Ms` headers. A per-request fallback list replaces the catalog chain for that one call; the retry count wraps each candidate in an exponential-backoff loop (cap 5 retries, 5 s backoff). Trace spans carry `opod.fallback.source = catalog | request`, the audit log captures every override, and `opod_router_fallback_total{reason}` splits `catalog` / `per-request` / `retry`. CLI: `opod connect curl --retries 3` bakes the header into the snippet.
- **Typed fallback lists** — catalog entries can declare class-specific fallback chains: `fallback_on_context_length: [longctx-a]` (prompt too long) and `fallback_on_content_policy: [permissive-a]` (vendor refusal). The router classifies the primary's failure (sentinel `errors.Is` first, then heuristic substring match — covers llama.cpp's `n_ctx`, OpenAI's `maximum context length`, Anthropic refusals, Bedrock guardrails) and switches the remainder of the chain to the matching typed list. Generic `fallback:` still wins when no typed list matches. Span attribute `opod.fallback.classifier = generic | context-length | content-policy`; metric `opod_router_fallback_total{reason}` adds the same labels. `opod model info` renders all three chains.
- **Placement cooldown (circuit breaker)** — a worker that returns `placement_allowed_fails` consecutive engine errors gets parked for `placement_cooldown_seconds`. The router's `pick()` skips it until the cooldown expires; a single success after expiry resets the counter. Per-node, in-memory (rebuilt on restart). Env: `OPOD_PLACEMENT_ALLOWED_FAILS`, `OPOD_PLACEMENT_COOLDOWN_SECONDS`. New gauge `opod_router_cooldowns_active`; admin `/admin/v1/nodes` decorates each row with `cooldown_until`; dashboard Nodes tab renders a 🚫 cooldown badge with seconds-remaining. Both knobs must be > 0 to enable — either zero preserves the historical "always try the worker" behavior.
- **Sticky sessions (KV-cache locality)** — when `router.sticky_session_ttl_seconds > 0`, the router pins each (user_id, model) tuple to the worker that served its previous successful request, so multi-turn chats reuse the same node's KV cache between turns. The pin refreshes on each successful pick and expires after the TTL of inactivity. Bypassed for anonymous requests (no auth key) and for `model=auto` (auto-resolution may change between turns). Sticky pick is overridden when the previously-pinned node is in cooldown or fails the heartbeat check — falls through to the normal least-loaded pick. Env: `OPOD_STICKY_SESSION_TTL_SECONDS`. New counter `opod_router_sticky_hits_total{outcome=hit|miss|expired}`.
- **RPM/TPM rate limits** — per-key `--rpm` (requests/min) and `--tpm` (tokens/min) ceilings backed by in-memory leaky buckets. On admit the middleware deducts 1 RPM token + an upfront prompt-size estimate from TPM; on overflow returns HTTP 429 `rate_limited` with `Retry-After` reflecting bucket refill time. After the response, `recordUsage` reconciles the estimate against actual prompt+completion tokens (refunds on over-estimate, deducts on under-estimate). CLI: `opod token create alice --rpm 60 --tpm 100000`, `opod token edit k_abc --rpm 30 --tpm 50000`. Dashboard: per-row RPM/TPM cells + inline edit prompt + create-form inputs. Buckets are per-process; reset on leader restart (acceptable for v1).
- **Time-bucketed usage breakdown** — new `GET /admin/v1/usage/breakdown?bucket=day&since=YYYY-MM-DD&group_by=user,model` returns aggregated prompt/completion/request counts. Bucket ∈ {`hour`, `day`, `month`, `total`}; `group_by` is any comma-separated subset of {`user`, `model`, `protocol`, `outcome`}. Defaults: last 30 days, day buckets. CLI: `opod usage --by user,model --bucket day --since 2026-05-01`. Dashboard Usage tab adds a Breakdown panel with bucket/group/since controls and a totals footer. New indexes on `usage(ts)` and `usage(model, ts)` keep the query under 100 ms on tens of thousands of rows.
- **Per-call $ cost tracking** — every usage row now stores a `cost_usd` snapshot computed at write time, so historical totals stay correct when vendor pricing changes. Pricing comes from (1) the catalog entry's optional `price_prompt_usd_per_1k`/`price_completion_usd_per_1k` fields, then (2) a built-in vendor table (`internal/models/vendor_pricing.go`) covering current Claude and OpenAI rates with longest-prefix matching. Open-weight catalog entries default to `$0` (no cost tracked). Surfaced in: `/admin/v1/usage/summary` (`cost_usd_total`, `cost_usd_today`, per-model `cost_usd`), `/admin/v1/usage/breakdown` (`cost_usd` column + total), CLI `opod usage --summary` ($ spent line) and `opod model info` (pricing row), and the dashboard's new "$ today" KPI card.
- **Monthly + dollar budgets** — per-key spend caps that compose with AND semantics. A key with `$10/day AND $100/month AND 1M tokens/day` is refused as soon as any single budget hits its limit. Windows: `day`, `week`, `month` (UTC boundaries). Units: `tokens` or `usd`. Lazy reset at admission time means there's no cron — the next request after window expiry rolls the counter. Overflow returns HTTP 429 with `error.type=budget_exceeded` and `{unit, window, current, limit, reset_at, retry_after}` so clients can show a meaningful "you've spent $100 this month" message; every refusal lands in the audit log. CLI: `opod token budget add k_abc --window month --limit 100 --unit usd`, `opod token budget ls k_abc` (shows utilization %), `opod token budget rm k_abc 4`. Admin: `GET/POST /admin/v1/tokens/{id}/budgets`, `DELETE /admin/v1/tokens/{id}/budgets/{bid}`. Dashboard Tokens tab gains a "budgets…" action with utilization bars + an add form.
- **Standard rate-limit response headers** — every `/v1/*` response now carries OpenAI-style `X-RateLimit-Limit-Requests`, `X-RateLimit-Remaining-Requests`, `X-RateLimit-Reset-Requests` and the `*-Tokens` counterparts (when the key has RPM/TPM configured), plus an always-emitted `X-Opod-Request-Id` correlation token. Budget overflow adds `X-Opod-Budget-Reset-At`. The request id is propagated into the audit log's metadata column for `model_not_allowed`, `budget_exceeded`, and `router.override` rows so `opod audit --json | jq` can correlate response → audit entry.
- **OpenAI-compatible hosted gateway adapters** — passthrough to OpenRouter, Groq, Together, Fireworks, Cohere, Mistral La Plateforme, and Perplexity. Slash-namespaced prefixes (`openrouter/<model>`, `groq/<model>`, `cohere/<model>`, etc.) are recognized by `Vendor()` and routed through a shared OpenAI-shape proxy that strips the prefix from the request body's `model` field before forwarding. Env: `OPENROUTER_API_KEY`, `GROQ_API_KEY`, `TOGETHER_API_KEY`, `FIREWORKS_API_KEY`, `COHERE_API_KEY`, `MISTRAL_API_KEY`, `PERPLEXITY_API_KEY`. URLs default to each vendor's public endpoint; override per-vendor via `router.fallback.{openrouter,groq,together,fireworks,cohere,mistral,perplexity}_url`. Vendor pricing entries seeded for Cohere (Command R+, Command R), Mistral (Large/Medium/Small/Codestral/Ministral), and Perplexity (Sonar Pro/Reasoning/Sonar). **Vertex full body translation** (OpenAI/Anthropic → `generateContent`) is the missing half — the existing ADC-probe stub still returns 501 with an actionable hint for `gemini-*` ids.
- **Registry providers (DeepSeek + 13 more)** — a table-driven provider registry (`internal/api/providers.go`) adds `deepseek/`, `cerebras/`, `nvidia/`, `gemini/` (OpenAI-compat), `huggingface/` with known-stable base URLs, plus `zai/`, `ollama-cloud/`, `github/`, `cloudflare/`, `ovh/`, `kilo/`, `pollinations/`, `llm7/`, `opencode-zen/` which require `<NAME>_BASE_URL` (Opod refuses to ship a guessed endpoint). Each is a single table row inheriting prefix routing, the key-pool rotation, and dispatch. `Vendor()` falls through to the registry after the built-in rules, so bare `gemini-*` still routes to Vertex while `gemini/<id>` hits the OpenAI-compatible path. Keys via `<ENV>` + numbered `<ENV>_2..N`; URL override via `<NAME>_BASE_URL`.
- **Multi-key rotation + 429 failover (per provider)** — stack several keys for one provider (`GROQ_API_KEY`, `GROQ_API_KEY_2`, … `_N`) and the egress layer (`internal/api/keypool.go`) rotates across them round-robin, parking any key that returns 429 / 5xx / a transport error (honoring `Retry-After`) and retrying on the next. The client never sees the rate limit; the last key always streams through so a real error still surfaces once all are exhausted. Mirrors the router's node circuit-breaker, keyed on `(vendor, key)`. Single-key setups behave exactly as before.
- **Cross-provider routing chain (`model="auto"`)** — a persisted, user-ordered list of model ids (`route_chain` table; `RouteStore`) that Opod walks for `model="auto"`: each candidate is tried top-to-bottom via a `failoverWriter` that swallows a rate-limit/transient attempt and advances, or commits the first success (and always the last candidate). Key rotation handles *within* a provider; the chain handles *across* providers; a local model pinned last is the always-available floor. Each protocol only tries entries it can serve (`openAICompatible` / `anthropicCompatible`), sidestepping cross-protocol translation. A free → cheap → paid → local default is computed from configured providers. Manage via `opod route ls/set/add/mv/rm/reset` or the dashboard **Routing** tab (drag-reorder); both write the audited `GET/PUT/DELETE /admin/v1/route`.
- **Observability callbacks (webhooks + Langfuse)** — usage and audit events fan out to external sinks configured under `observability.callbacks` in `config.yaml`. Each sink runs in its own goroutine with a bounded queue (default 100); a slow receiver is non-blocking on the hot path — overflow events are dropped and counted on `opod_callback_sent_total{outcome="dropped"}`. Webhook driver signs every payload with HMAC-SHA256 (`X-Opod-Signature: sha256=<hex>`) when a `secret` is set; events filter (`events: [usage, audit]`) lets a sink opt out per kind. Langfuse driver maps usage events into a "generation" observation against `/api/public/ingestion`. New gauge `opod_callback_queue_depth{sink}`. Admin: `GET /admin/v1/callbacks` lists the configured sinks; `POST /admin/v1/callbacks/test[?sink=name]` fires a synthetic `test` event so an operator can verify wiring before real traffic. Fallback events are not yet wired (router→callbacks dep wasn't worth the layering); only usage and audit ship today.
- **`/v1/rerank` + `/v1/audio/*` endpoint shells** — `/v1/rerank` proxies to a llama-server instance (which has native rerank support since b3580) and emits the same Cohere-shape response clients expect. `/v1/audio/transcriptions` and `/v1/audio/speech` are wired routes that proxy to optional `OPOD_WHISPER_ENDPOINT` / `OPOD_PIPER_ENDPOINT` configured engines; unconfigured returns HTTP 501 with the exact env var to set + project link (whisper.cpp, piper). Each endpoint records a usage row with `protocol = rerank | audio-asr | audio-tts` so the usage breakdown groups them naturally.
- **Router request hedging** — opt-in per-request fan-out. With `router.hedge_replicas: 2` in `config.yaml` (capped at 3), a client adding `opod.hedge: true` to the body (or `X-Opod-Hedge: 1` header) fires the chat request to the top-N least-loaded workers concurrently and returns whichever stream opens first; the losers' contexts are cancelled and their inflight gauge is decremented. Tail-latency win for ~2× the engine cost. Hedging skips retry / fallback / latency reorder — the operator already accepted the cost trade. Metric: `opod_router_hedge_total{outcome=win|cancelled|error}`. Falls back to the normal single-pick path when fewer than 2 eligible workers exist (cooldowns + stale heartbeats are excluded).
- **Response cache (embeddings)** — deterministic embedding requests are cached so repeat queries (RAG retrieval, batch evals) skip the engine entirely. Two drivers: in-memory LRU (default, bounded by `max_entries`) and SQLite-backed (survives leader restart, reuses `~/.opod/state.db`). Cache key is a sha256 of the canonicalized request body — JSON object keys sorted alphabetically, ephemeral fields like `user` stripped — so byte-different but semantically-equal requests collide. Per-request opt-out via `Cache-Control: no-cache` / `no-store`. Per-tenant scoping via `opod.cache.namespace` in the request body. Response carries `X-Opod-Cache: hit | miss`. Metrics: `opod_cache_hits_total{path}`, `opod_cache_misses_total{path}`. Admin: `GET /admin/v1/cache/stats`, `DELETE /admin/v1/cache?namespace=X` or `?all=1`. Config: `observability.response_cache: { enabled, driver, max_entries, default_ttl_seconds }`. **Chat completion caching** is deferred — properly replaying a streamed response from cache deserves its own design pass.
- **Guardrails (pre-call hook + webhook driver)** — `observability.guardrails` in `config.yaml` chains synchronous content checks against an external service before the engine sees the request. Each row picks a mode (`pre` blocks/rewrites; `logging_only` observes) and a driver (`webhook` today). The webhook POSTs the request body and reads `{"action":"allow|block|rewrite|flag","reason":"…","replacement":<new body>}`. Pre-mode block returns HTTP 403 `guardrail_blocked` with the guardrail name + reason; rewrite swaps the body and the chain continues. `fail_open: true|false` chooses Allow vs Block on guardrail unreachable. Metric `opod_guardrail_action_total{name,action}`; every block / flag lands in the audit log under `guardrail.<action>`. Post-call mode is wired in config but not yet evaluated — that needs careful streaming-response handling and is queued for follow-up. Specific drivers (Presidio, Bedrock Guardrails) work today by writing a thin shim that translates between their APIs and the documented webhook contract.
- **Key expiration (TTL)** — API keys can carry an `expires_at` timestamp. The auth middleware returns HTTP 401 `key_expired` once the timestamp is past. CLI: `opod token create alice --ttl 7d` (Go-style durations with `d` extension for days, or `--expires-at YYYY-MM-DD` for absolute dates), `opod token expire k_abc [--in 1h]` to flip immediately or in the near future, `opod token renew k_abc --ttl 30d` to extend. Admin: `POST /admin/v1/tokens` accepts `expires_at` or `ttl_seconds`; `PATCH /admin/v1/tokens/{id}` accepts both (use `expires_at: null` to clear). Dashboard Tokens tab shows a per-row badge: green "active · 14d", amber "expires in 3d" (≤ 7 days), red "expired" / "revoked". New "expiry…" action opens a modal with extend/set-date/clear options.
- **Per-request routing sort (`:floor` / `:nitro` / `opod.sort`)** — OpenRouter-compatible routing shortcuts: `model: "qwen3.6-27b:floor"` walks the candidate chain cheapest-first (catalog + vendor pricing table; free local models always beat paid egress), `:nitro` highest-tokens/sec-first. Explicit `opod.sort: price|latency|throughput` body field or `X-Opod-Sort` header wins over the suffix. Latency ranks by rolling per-model p95; throughput by median tokens/sec over the last 50 requests (engine-reported completion tokens, falling back to delta-event counts) — both warm up with traffic, unsampled models rank last. The suffix is stripped before model resolution, so engines, usage/cost records, and per-key allowlists all see the base id (`["x"]` authorizes `x:floor`). Works on `/v1/chat/completions`, `/v1/messages`, and `/v1/embeddings` (which also gains X-Opod-* override support it previously lacked). Explicit per-request sort suppresses the latency-pressure auto-reorder; unknown sort values are ignored rather than 400'd (forward compat). Span attr `opod.sort`; audit-logged under `router.override` like every routing override.
- **Pre-flight source probe on model add** — `opod model add` (and the dashboard's Add-custom-model / `POST /admin/v1/models`) now HEAD-checks the upstream before installing: a typo'd `hf:owner/repo` or a renamed Ollama tag is refused immediately with the exact URL that 404'd, instead of "succeeding" and surfacing later as a mystery engine-launch crash (vLLM/MLX/llama.cpp driver Pulls are no-ops, so the old failure was deferred and misattributed). Gated HF repos (401/403 license walls) count as existing; network errors / 5xx only warn — a flaky connection never blocks an install. Escape hatch: `OPOD_SKIP_SOURCE_CHECK=1`. `--dry-run` gains a "Source check" row. The nightly catalog live check now runs on the same shared probe (`internal/models/probe.go`), so CI and the install path can't drift apart.
- **Memory lifecycle (admission + evict-and-swap + release)** — Opod now distinguishes *installed* (on disk, routable) from *resident* (occupying RAM, via Ollama `/api/ps`) and manages the latter. `opod model load <id>` admits against a per-node budget (total RAM minus a 20% reserve; footprint = weights + ~20% overhead) and **refuses rather than overcommit**; `--swap` evicts least-recently-used, non-pinned models — each victim is *drained* (placement flips to `draining` so the router stops routing to it; in-flight requests get up to `placement.drain_timeout_seconds` to finish) before the `keep_alive:0` unload, and every eviction lands in the audit log (`model_evicted` with who / for-what / bytes-freed). `--pin` exempts a model from eviction *and* Ollama's idle TTL (`keep_alive:-1`). Loaded/pinned models persist as **desired placements** (new SQLite table) and are restored in priority order on the next `opod up`. `opod model ps` / `GET /admin/v1/memory` show live residency + free budget; `POST /admin/v1/models/{id}/load` returns typed `needs_swap` / `blocked_by_pinned` / `impossible` errors; the dashboard Models tab gains an Engine-memory card (usage bar, pin badges) and a per-row load button with an eviction-confirm dialog. `opod down` now **releases engine memory by default** (`--no-unload` opts out); Ctrl-C of `opod up` keeps the fast-restart behavior. `opod up --exclusive` (or `placement.exclusive` / `OPOD_EXCLUSIVE=1`) enforces one resident model per machine. Engines without a residency protocol (vLLM, MLX-LM, llama-server) degrade to budget-only admission; Opod-spawned llama-server processes already free memory via the supervisor's process-group kill on shutdown.
- **Vision** via `image_url` content blocks on `/v1/chat/completions` (Ollama path); **embeddings** via `/v1/embeddings`
- **Typed `engine_unreachable` errors** with engine name, endpoint, and the exact command to start it (`ollama serve`, `mlx_lm.server …`, etc.) when the upstream engine isn't responding
- **Engine health watchdog** on auto-spawned engines (force-restart after 3 consecutive failures, covers hung `llama-server`)

## CLI ergonomics

- Interactive picker (`opod model add|info|remove`, `opod connect` with no ID launches a fuzzy-filter picker — ↑↓ / enter)
- Shell completion (`opod completion bash|zsh|fish`)
- Colored output (auto-detects TTY; respects `NO_COLOR` / `OPOD_NO_COLOR`)
- `--json` on every read command (`model search/ls/info`, `status`, `usage`, `audit`) for scripting
- `opod usage --summary` / `opod audit --summary` aggregate views (top models, p50/p95/p99, error rate, unicode-block sparkline) — same data as the dashboard home view
- First-run wizard on `opod up` (picker-driven starter-model install; skip with `--no-wizard`)
- Real progress bar on `opod model add` with bytes/sec + ETA (smoothed over a 1 s window)
- `--dry-run` on `opod model add` (preview download size, engine, RAM check, ETA without pulling weights)
- Confirmation prompt on `opod model remove` / `opod node remove` / `opod shard remove` (skip with `--yes`)
- `opod model unload <id>` drops a model from engine RAM without deleting weights (Ollama; other engines return a soft warning)
- Did-you-mean for command typos at every level (Damerau-Levenshtein over the registered command list) — both top-level verbs (`opod modle` → `model`) and nested sub-verbs (`opod model lst` → `model ls`, `opod token creat` → `token create`); a prefix match is preferred, and the hint always points at `opod <group> --help`

## Multi-node + sharding

- `opod token create --node` issues a worker join token
- `opod join <leader>?token=…` registers + starts a worker HTTP server bound to the LAN / tailnet address
- Workers run their own engine (Ollama / vLLM / MLX); leader proxies inference requests to them
- **Router** picks the right node per request: local-preferred if the model is loaded locally, otherwise least-loaded worker that has the model
- **Heartbeat-freshness pre-dispatch check** — pick() skips workers whose last heartbeat exceeds `SetHeartbeatMaxAge` (configurable) and falls back to local rather than waiting for the engine call to time out
- **Heartbeat carries loaded models** every 5 s; leader reconciles the placements table automatically
- Agent handles auth errors gracefully (401 → exit, 404 → re-register, transient → exponential backoff)
- **Sharding auto-orchestration** — `opod shard create <model> <N>` picks N workers, launches `rpc-server` on each via the worker process-supervisor API, launches the coordinator `llama-server --rpc <list>`, registers the placement, and the Router routes requests to the coordinator transparently. Web UI exposes the same in the Shards tab.
- **Auto-distribution of GGUF weights** from leader to shard hosts (sha256-verified)
- **Coordinator placement on the strongest worker** (not just leader); override via `OPOD_COORDINATOR_NODE`
- Process supervisor (`internal/agent/supervisor.go`) — Start/Stop/Logs with TCP-port readiness probe, used by the leader for the coordinator and by workers for `rpc-server`
- Shard crash auto-restart (up to 5 attempts with exponential backoff) before declaring `crashloop`

## Routing intelligence

- **Catalog fallback chains** — any catalog entry can declare `fallback: [next-id, …]`; the router walks the chain on engine error / 5xx / timeout / model-not-loaded. Transparent to clients; logged via structured slog; counted in `opod_router_fallback_total`
- **Latency-aware fallback** (Bet #1) — opt-in via `router.latency_fallback_p95_seconds` (env `OPOD_LATENCY_P95_SECONDS`). When a model's recent p95 exceeds the threshold, the router walks the fallback chain for a faster candidate to try first. O(1) ring-buffer per model for the rolling window.
- **`SetMaxFallbackAttempts`** caps how many candidates the router will walk before giving up; `opod_router_fallback_total{reason=cap-exhausted}` for visibility
- **Bedrock SigV4 signing** for `anthropic.*` family (non-streaming); **Vertex ADC probe** wired (body translation pending)

## Multi-tenancy

- Per-user API keys with scopes (admin / user / node), daily token quotas, full audit log
- Usage metering — every request recorded with model / protocol / tokens / latency
- **HMAC-SHA256 signatures** on control-plane traffic so the worker token isn't sent on the wire after the initial join. Set `OPOD_REJECT_BEARER=1` on workers to refuse the bearer-fallback path entirely.
- OIDC for the web UI — **planned**; the UI uses a pasted admin key (or the localhost auto-bootstrap) for now

## Observability

- Prometheus metrics at `/metrics`:
  - `opod_requests_total{model,protocol,outcome}`, `opod_request_duration_seconds`, `opod_request_tokens_total{model,direction}`
  - `opod_model_loaded{model,node}`, `opod_node_up{node,hostname}`
  - **Router subsystem**: `opod_router_picks_total{path,outcome}`, `opod_router_inflight{node}`, `opod_router_fallback_total{op,reason}`, `opod_router_attempt_duration_seconds{model,outcome}`
- **OpenTelemetry / OTLP traces** end-to-end (HTTP → router → engine) across all four drivers, with prompt / completion token counts as span attributes. Set `OPOD_OTLP_ENDPOINT` to a collector URL; empty disables tracing with zero overhead.
- Structured slog events for fallback decisions and stale-heartbeat skips
- Reference Grafana dashboards in [`dashboards/`](dashboards/) — cluster overview, per-model, per-node

Embedded as a single HTML file (Tailwind via CDN). Tabs: Dashboard, Connect, Playground, Nodes, Models, Shards, Tokens, Usage, Audit, Settings.

## Release + ops

- GitHub Actions CI on every push (vet, race tests, build)
- Auto-release workflow: every `feat:` / `fix:` commit on `main` runs `goreleaser` and cuts a new tag (`BREAKING CHANGE:` footer triggers a major bump; otherwise `feat` → minor, `fix` → patch)

- One-line install (`curl -fsSL https://raw.githubusercontent.com/opod-io/opod/main/installer/install.sh | sh`) pulls the latest release for the host's platform and verifies the SHA-256 against the published `checksums.txt`
- `opod update` performs an in-place binary swap (or stages next to the existing binary for sudo installs)
- Two-node verification: in-process E2E test (`internal/controlplane/two_node_e2e_test.go`) + manual walkthrough (`docs/TWO_NODE_VERIFICATION.md`) + a 30-second smoke script (`scripts/two-node-smoke.sh`)

## Security & hardening

Findings from a full-codebase review, fixed in the `fix/code-review-findings` series.

- **Secrets no longer leak via `opod config show`** — all secret config fields (vendor API keys, the multi-key rotation pool, webhook/Langfuse/S3 credentials, guardrail bearer) now carry `json:"-"` in addition to `yaml:"-"`. The CLI's local-fallback path (used when the leader is unreachable) marshals the config to JSON; without the tag it printed live keys in plaintext. `config show` now also only falls back to the local view on a genuine connectivity failure — an auth/5xx error from the leader is surfaced instead of being masked by a CLI-loaded dump.
- **One-time secrets warn when written to a non-terminal** — `opod token create` and the first-run admin key in `opod up` now emit a stderr warning when stdout is piped/redirected/CI (where the secret can land in shell history or logs), via a shared `emitSecret` helper. The value still goes to stdout so automation keeps working.
- **Opt-in SSRF protection for outbound webhook/guardrail clients** — new `block_private_targets` config (env `OPOD_BLOCK_PRIVATE_TARGETS`, default off). When on, the observability-callback and guardrail webhook HTTP clients refuse to connect to loopback, link-local (incl. the `169.254.169.254` cloud-metadata IP), unspecified, RFC-1918, RFC-4193 ULA, and RFC-6598 CGNAT addresses. The check runs in the dialer's `Control` callback against the post-DNS IP, so it also defeats DNS-rebinding. Default-off because on-prem webhooks at private addresses are common; the new `internal/httpsafe` package centralizes the guarded client. (Catalog probing is intentionally *not* guarded — its targets are legitimately local engines like Ollama at `127.0.0.1`.)
- **Audit log records the real TCP peer, not a spoofable header** — `auditMiddleware` logged `r.RemoteAddr`, which `middleware.RealIP` has already rewritten from `X-Forwarded-For`, so a caller could forge the audit "target". It now uses the pre-RealIP peer (`realRemoteAddr`), the same source the loopback-gated `bootstrap-key` endpoint already trusts.
- **Forwarded headers gated behind `trust_proxy_headers`** — `defaultBaseURL` (invite/connect cards) honored `X-Forwarded-Host`/`-Proto` unconditionally when `external_url` was unset, so a spoofed header could mint a share card pointing recipients at an attacker host. Those headers are now honored only when the new `trust_proxy_headers` config (env `OPOD_TRUST_PROXY_HEADERS`) is set; default-off behavior uses `r.Host`. Set it when Opod runs behind a trusted reverse proxy.
- **CLI robustness cleanups** — `opod token budget add` builds its request body with `json.Marshal` instead of `fmt.Sprintf`+`%q` (which escapes for Go, not JSON); `opod shard rm` and the budget endpoint `url.PathEscape` the model/key in the request path; `truncStr` (usage tables) truncates by rune so multibyte characters aren't split into mojibake, and handles the `n≤1` edges; and `opod status` / `opod node drain` now surface store errors instead of masking them as "no models"/"no such node". `opod join` warns when a join token would be sent over cleartext `http` to a non-local leader. (Regression test added for `truncStr`.)
- **SQLite `busy_timeout` set to avoid spurious `SQLITE_BUSY`** — one `*sql.DB` is shared across heartbeats, usage records, budget increments, and the cache reaper, so concurrent writes are routine. WAL was enabled but no busy timeout, so a second concurrent writer failed immediately instead of waiting. Added `busy_timeout(5000)` to the connection pragmas (preferred over `SetMaxOpenConns(1)`, which would also serialize reads).
- **`OPOD_EXCLUSIVE` now parsed with `strconv.ParseBool`** — it previously matched only the exact strings `"1"`/`"true"`, unlike the other boolean env knobs; `"TRUE"`/`"yes"`/`"0"` now behave as expected.
- **Audio/rerank proxies strip hop-by-hop headers** — `/v1/rerank` and `/v1/audio/*` copied *all* upstream response headers (including `Content-Length`, `Transfer-Encoding`, `Connection`) before `io.Copy`, which can produce a length/body mismatch when the upstream reply is chunked. They now route through the shared `copyUpstreamHeaders` helper the egress proxy already used.
- **Bedrock client cached per region** — the `bedrockruntime` client was a single global keyed implicitly by the first region seen, so a second configured region silently reused the first region's client. Now cached per region in a mutex-guarded map.
- **Sticky sessions now pin on success, and the hit-rate metric is accurate** — the `(user, model)→node` pin was refreshed at *pick* time, so a node that was selected but then failed its engine call still got pinned and steered the next turn back to the just-failed node. The pin now refreshes on the Chat/Embed success path alongside the outcome record. Separately, `opod_router_sticky_hits_total` double-counted: `stickyPick` emitted `miss`/`expired` and then `pick` unconditionally emitted another (default `miss`), so every non-sticky request logged two events. `pick` now records an outcome only when a pin was actually consulted.
- **`opod update` extraction hardened** — `extractTarGz` now skips non-regular tar entries (symlinks/hardlinks/devices — previously a symlink fell through and was written as a regular file containing its target path) and rejects absolute paths and dir-escapes via `filepath.Rel` instead of a weak `".."` substring check. Cross-filesystem install is fixed too: the new binary is staged in the install dir and renamed within it (a rename straight from the temp dir hit `EXDEV` and was misreported as "needs sudo"); a genuinely unwritable install dir now parks the binary in a persistent temp file with a `sudo install` hint. And `lookupChecksum` normalizes `*`/`./` filename prefixes so a present checksum isn't mistaken for "not listed" (which fails the install closed). (Regression tests added.)
- **Sharded GGUF upload now HMAC-signs the request** — the upload to a worker's `/v1/process/upload` set only the bearer header; unlike every other worker call (file check, process start/stop) it never called `auth.SignRequest`, so a worker running `OPOD_REJECT_BEARER=1` rejected it with 401 and sharded-model distribution silently failed. Now signed (signing covers method/path/ts only, so the streamed body is untouched).
- **HF GGUF downloads are integrity-checked and concurrency-safe** — `downloadFromHF` now verifies the downloaded byte count against the server-declared `Content-Length` and fails on a truncated (complete-but-short, HTTP 200) body instead of renaming it into place and fanning it out to workers; and it writes to a unique `os.CreateTemp` `.partial-*` file so two concurrent downloads of the same entry can't interleave into one file.
- **Dev mode (`require_keys: false`) no longer locks out cluster admin** — when keys were disabled the auth middleware set no scope, so `ScopeFrom` returned `""` and every `RequireScope("admin")` / `RequireScopeAny("admin","node")` check 403'd — a keyless cluster couldn't register nodes or be administered at all. Dev mode now injects an `admin` scope. (Regression test added.)
- **Admin API request bodies are now size-capped** — `limitRequestBody` (`MaxBytesReader`, 32 MiB default) was applied only to the `/v1` group; every `/admin/v1` handler `json.Decode`d an uncapped body, and a node-scope token (reachable via `/nodes/register` + `/heartbeat`) could stream an unbounded body. The cap now wraps the admin group too.
- **Langfuse no longer silently drops every event on a half-set credential** — the worker goroutine starts only when both `public_key` and `secret_key` are present, but `Subscribes` previously returned true whenever *either* was set. With one key configured, events were enqueued to a channel nothing drained — the queue filled and every usage event was dropped, with the queue-depth metric climbing forever. `Subscribes` is now gated on the same `started` flag as the worker.
- **Fixed a data race in the latency tracker** — `latencyStats.p95` / `.throughput` grabbed the per-model ring buffer under the read lock, released it, then called `snapshot()` (which reads the ring's `data/head/full`) outside the lock — racing `record()`'s `push()` under the write lock. Since these run on the hot routing path (`reorderByLatency` / `sortChain`), it tripped under concurrent load. The snapshot is now taken while the read lock is held.
